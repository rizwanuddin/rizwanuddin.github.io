DriftWatch

Semantic narrative-drift detection platform

A full-stack tool for investigating how the public story around a company changes over time. You pick a subject, a topic and a date range. DriftWatch pulls historical news, throws out irrelevant articles, scores how the meaning shifts, and plots a timeline where every point links back to its source.

What I built

  • A 3-stage relevance gate: subject or alias match, optional official-domain filter, and a semantic threshold on 384-dimensional embeddings.
  • Two separate scores using pgvector cosine distance: drift from the tracked topic, and shift from a frozen baseline of the earliest 5 relevant articles.
  • Representative sampling: a 10-year range uses at most 12 windows instead of about 120 monthly ones (up to 90% fewer planned requests), with retries and per-window failure isolation.
  • A Docker Compose stack of API, worker, PostgreSQL with pgvector, and Redis/RQ, plus 5 versioned migrations.

Crypto Exchange

Order-matching backend, built from scratch

An exchange backend with a custom matching engine behind a FastAPI REST API. Trades and order-book updates stream live to a browser frontend.

What I built

  • A matching engine with price-time priority (best price first, then oldest order) that partially fills an order across multiple resting orders.
  • Transactional order handling with PostgreSQL row-level locking, so competing orders can't claim the same liquidity.
  • Per-symbol WebSocket channels that stream trades and book updates, with an isolated order book for each trading pair.
  • Separate layers for routes, services, the matching engine and repositories, with Pydantic validation (positive price and quantity) before anything reaches the database.

    NullStack

    Self-hosted code execution platform

    Runs untrusted Python, SQL and Java in throwaway Docker containers, then gives automated code-review feedback from a local LLM. The whole platform comes up with one Docker Compose command.

    What I built

    • A Streamlit frontend and a Flask REST API that accept code submissions.
    • An ephemeral container for every run, with network isolation, a 128 MB memory cap and a 5-second timeout.
    • Code review from a local model (Phi-3 Mini, 3.8B parameters) through Ollama, with no API cost and no code leaving the machine.

I'm now rebuilding it solo as a platform where staff edit a private draft and publish it to a permanent QR-code URL, so changing a price never means reprinting a menu.

    Built so far

    • A modular FastAPI monolith on PostgreSQL, chosen over microservices because the features share relational data and nothing measured says they need splitting.
    • Health and readiness endpoints; readiness returns 503 when the database is unreachable.
    • Request middleware that assigns every request an ID and logs its duration as structured JSON.
    • Typed configuration, SQLAlchemy sessions and Alembic migrations, with Ruff, Mypy and Pytest checks behind an 80% coverage gate.
